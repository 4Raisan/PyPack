# PyPack 0.1.2

Search, safety and responsiveness fixes. The package-management interface is unchanged apart from the additions below.

## Search

- Correct a mistyped name instead of listing only literal substring hits. `numpi` now finds **numpy**, `reqeusts` finds **requests**, and `pilllow` finds **pillow**.
- Rank a widely downloaded close spelling above an obscure exact namesake, which is what separates `numpy` from `NuMPI`. An exact name still outranks its own popular extensions, so `django-rest` stays first.
- Show 30-day download counts beside every result and highlight names outside the published top-download list, making typosquats visible before you check the box.
- Load the 926,315-name index once per process instead of re-reading 14 MB on every search. Searches went from roughly 400 ms to 5–15 ms.
- Serve a stale cached index when PyPI is unreachable, rather than returning no results, and write the cache atomically so an interrupted download cannot leave a truncated index.
- Move caches out of the local-app-data root into a per-platform cache directory, reusing a fresh pre-0.1.2 cache so upgrading does not re-download the index.

## Safety

- Add **Stop** to cancel a running install or upgrade, and kill the whole `pip` process tree when stopping or closing the window, so `pip` is never left writing to `site-packages` unattended.
- Run `pip check` after installs and bulk upgrades and report dependency conflicts instead of implying success.
- Detect a read-only `site-packages` (typically an all-users Windows install) with a non-blocking permission check and explain it, rather than surfacing a raw permission error. Interpreter discovery never writes to `site-packages`, so security software that intercepts such writes cannot stall it.
- Add **New venv** so an OS-managed or read-only interpreter no longer dead-ends a GUI user into a terminal command.
- Honour `PIP_INDEX_URL` in the connectivity check, so a private mirror is not reported as offline.

## Interface and CLI

- Write a rotating activity log next to the cache, so failures of the console-hidden Windows executable can still be diagnosed.
- Add `--help` and `--version`; `--help` now exits 0. `search` prints JSON instead of a Python list repr.
- Send a User-Agent derived from `VERSION` rather than a hardcoded `PyPack/1.0`.
- Pick the first available font family instead of hardcoding Windows-only Segoe UI and Consolas.
- Show the version in the window title.

## Build and verification

- Bundle `VERSION` into the Windows executable and both Unix launchers so `--version` works from a download.
- Refuse to build a source ZIP from a dirty working tree, so the archive cannot diverge from the release commit; `--allow-dirty` opts out for local iteration.
- The standalone Unix launchers now check for tkinter before opening the GUI, matching the source launcher, and point at the right package for each distribution.
- Run the GUI tests under a virtual display on Linux, so the window is exercised on all three platforms rather than only Windows and macOS.
- Add build-provenance attestation for every release asset, Dependabot for actions and build dependencies, and a security policy.
- Grow the offline suite from 21 to 87 checks. Statement coverage of `pypack_setup.py` rose from 23% to 75%, and the GUI layer from 0% to 86%.

Windows downloads remain unsigned; verify them with `SHA256SUMS.txt` and `gh attestation verify`. Linux/macOS require Python 3.10+ and tkinter. Clean-machine Python installation is still validated manually.
